기능 명세

사용자가 쓰는 기능 단위로 정리했습니다. 기능마다 화면, API, 완료 조건, 범위 밖을 적었고, 업무 ID를 누르면 그 업무의 상세가 열립니다. 형식의 기준은 docs/01_interfaces.md, 화면은 docs/03_screens.md입니다.

시스템 구조

10/29 범위 축소안 기준. 브라우저는 계약방 API(backend)만 부릅니다. AI 호출, 해시 생성·검증, 체인 연동은 모두 backend 뒤에서 일어납니다(헌법 VII). 브라우저의 해시 재계산은 제3자 확인용 추가 기능입니다.

봉인 = A안

협의 이력은 오프체인 해시 체인, 최종본에만 양측 1회 EIP-712 서명. 서버가 대신 Sepolia에 제출하므로 사용자는 가스비가 없습니다.

4차 멘토링 안전장치

서명 데이터에 reviewHash(AI 검토 묶음 sha256)·nonce·deadline(확정+24시간). 컨트랙트는 재봉인 차단, landlord ≠ tenant.

WYSIWYS

backend가 서명 데이터 15필드를 DB 원천에서 다시 계산해 3곳에서 대조합니다. 다르면 409 SEAL_MESSAGE_MISMATCH.

AI는 설명만

비율·판정은 코드(T3)가 계산하고 AI는 그 숫자를 그대로 인용합니다. 유효/무효 단정, 코퍼스 밖 인용, 체결 권고는 가드에서 막습니다.

발표장 대비

데모 조항(S1·S3)과 서류 설명은 캐시, 자주 묻는 질문은 QA 테이블로 LLM 없이 답합니다. GPU 서버가 끊겨도 시연이 돕니다.

제출용 배포 (C8)

10/31에 로그인·계약 조회부터 먼저 배포하고 기능이 붙을 때마다 갱신. 네이버클라우드 서버 1대에 Caddy(HTTPS) → backend · ai-review · chain-service · PostgreSQL. ai-review는 GPU 서버 없이 QA 테이블·캐시만 답하고 나머지는 503 LLM_UNAVAILABLE.

calldata 비공개 (T1 보완)

지갑 창에는 15필드가 그대로 보이지만, 금액·특약은 중첩 구조체 LeaseTerms+salt로 묶여 컨트랙트에는 termsHash만 들어갑니다. 봉인 키는 keccak256(contractId, landlord, tenant).

옛 확인 무효화 (E5 보완)

작성 중 revision과 봉인 version을 나누고, AI 결과·서류 확인·위험 확인에 inputHash를 붙입니다. 내용이 바뀌면 예전 확인으로는 확정할 수 없습니다.

표현 바로잡기

서류 GREEN은 "안전한 집"이 아니라 "제공된 자료·규칙에서 추가 경고 없음". 최종 서명은 기록 묶음 전체에 대한 서명이며 각 행위 시점까지 따로 증명하지 않습니다.

GPU 서버 규칙

관리자 심형섭만 접속. 주소·계정·접속 명령은 저장소·Notion·단톡방에 쓰지 않습니다. 팀원은 mock 또는 노트북 Mi:dm Mini로 개발합니다.
